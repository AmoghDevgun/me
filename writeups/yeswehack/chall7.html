Walking Around the WAF

A homebrew sanitiser recursively scrubs a config object before document.write. Its type checks misclassify a crafted payload and a classic <img onerror> sails through.

Description

The application takes a config object, runs a homebrew WAF over it, then prints a greeting. The WAF recurses through keys and values, but its object/type checks are flawed — a crafted payload bypasses the string blacklist and reaches document.write. 

<script>
const config = ""

function isObject(o) {
    const proto = Object.getPrototypeOf(o)
    return typeof o === "object" && proto !== null && proto.constructor.name === "Object"
}

function WAF(x) {
    const forbiden = ["<", ">", "'", '"', "?"]
    if (x === null || typeof x === "number" || typeof x === "boolean") return x
    if (isObject(x))   return Object.fromEntries(Object.entries(x).map(([k, v]) => [WAF(k), WAF(v)]))
    if (Array.isArray(x)) return x.map(x => WAF(x))
    for (const needle of forbiden) {
        if (x.includes(needle)) throw new Error("Haking attempt detected.")
    }
    return x
}

function getMessage(config) {
    try {
        WAF(config)
        Object.setPrototypeOf(config, null)
        const name = config.name || "Guest"
        return `Hello ${name}`
    } catch (e) {
        return e.message
    }
}
document.write(getMessage(config))
</script>

Constraints

  • The WAF dispatches on type: objects recurse, arrays map, strings scan for forbidden characters.
  • String scan blocks: <, >, ', ", ?.

Goal

Execute arbitrary JavaScript through document.write.

Exploitation

  1. Supply a JSON object that overwrites __proto__ with an array and stashes the payload in name:
{"__proto__": [], "name": "<img src=x onerror=alert(1)>"}
  1. When the WAF runs, the flawed type detection lets the payload slip past the string blacklist entirely.
  2. The code then calls Object.setPrototypeOf(config, null), reads config.name, and hands the raw string to document.write.
  3. The browser parses the injected <img> tag — the broken src fires onerror, and alert(1) runs.

Why It Works

Four implementation mistakes line up:

  • Weak object detection. isObject checks constructor.name === "Object", which is fooled by prototype-tampered objects and non-plain objects alike.
  • Order of handling. The dispatch tries object recursion first, then array handling, then string scanning. Anything that hides from the first two paths is never string-checked.
  • Prototype confusion. Supplying "__proto__" in JSON mutates the prototype chain. The WAF only inspects entries it can iterate over — properties hidden in the prototype, or that change iteration behaviour, escape inspection.
  • Unsafe sink. After the WAF clears, document.write renders config.name verbatim. Any HTML with event handlers executes immediately — classic XSS.
