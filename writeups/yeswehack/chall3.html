Newline-Escaping the Blacklist

Two fields are injected into a <script> tag with a tight character blacklist. A single backslash turns the assignment into a one-liner and the alert fires.

Description

The challenge inlines two user-controlled fields directly into a <script> tag:

<script>
const age =
const name = ""
if (age > 18 && name.length) {
    document.write(`Welcome to my adult website ${name} 8=D`)
} else {
    document.write(`Go away`)
}
</script>

Constraints

  • age — maximum 2 characters, no blacklist.
  • name — blacklist forbids <, >, |, ', ".

Goal

Trigger alert(window.name).

Exploitation

  1. Put a single backslash in the age field: \.
  2. That backslash escapes the newline the server inserts, so the next line becomes a continuation of the age assignment instead of a new statement.
  3. Craft name to start with ; (closing whatever expression is open), drop the payload, and finish with // to comment out the trailing characters: ;alert(window.name)//.
  4. The combined script becomes syntactically valid and the alert runs — no angle brackets or quotes required.

Proof of Concept

  • age: \
  • name: ;alert(window.name)//

Why It Works

The trailing backslash on the age line escapes the literal newline in the generated source, so the parser stitches the name line onto the previous one. Starting name with a semicolon opens a fresh statement, and the trailing // comments out the rest. No <, >, or quotes are ever needed — the blacklist looks the wrong way.
