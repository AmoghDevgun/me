Polluting via constructor.prototype

Underscores are banned and the payload must be valid JSON, so __proto__ is off the table. Reaching Object.prototype through constructor.prototype works just as well.

Description

A page merges a JSON config into an options object via a recursive deepCopy, then conditionally executes options.code with new Function(options.code)(). Two defences guard the merge:

  • Keys containing _ are blacklisted — "__proto__" is out.
  • The config must be valid JSON, so there's no breaking out of the data layer with raw expressions.

Vulnerable Code

<script>
let options = { "_allowExecute": false };
const config = "";

function deepCopy(obj1, obj2) {
    for (let x in obj2) {
        if (typeof obj2[x] === 'object') {
            obj1[x] = deepCopy(obj1[x] || {}, obj2[x]);
        } else {
            obj1[x] = obj2[x];
        }
    }
    return obj1;
}

options = deepCopy(options, config);

if (options._allowExecute !== true) {
    delete options.code;
}

if (options.code) {
    (new Function(options.code))();
}
</script>

Why Common Payloads Fail

The standard prototype-pollution trick is to set "__proto__" in JSON to mutate the prototype. Here every key with _ is rejected, so that path is closed. The valid-JSON requirement also blocks non-JSON tricks for reaching the prototype chain.

The Trick — constructor.prototype

Even with "__proto__" off the table, every object inherits a constructor property whose prototype is the shared prototype object. The vulnerable deepCopy uses obj1[x] || {} when recursing — if obj1[x] is the built-in Object constructor (truthy), the function itself becomes the merge target, and its prototype property is the real Object.prototype.

Feed it "constructor": { "prototype": { ... } } and the merger writes straight into Object.prototype, creating inherited properties the script later reads.

Payload

Valid JSON, no underscores, plants code onto the prototype:

{ "constructor": { "prototype": { "code": "alert(window.name)" } } }

TL;DR

When __proto__ is blocked by an underscore filter and the input must stay JSON, you can still pollute prototypes through "constructor": { "prototype": ... }. The merger uses the existing constructor function as its target, so writes land on the shared prototype. delete options.code only removes the own property — the inherited one persists, and the page happily runs whatever it finds in options.code.
