Breaking a One-Pass Regex

Same script-injection shape as #3, but this time the blacklist is a regex that only looks once. Two forbidden characters slip past it cleanly.

Description

Two user-controlled fields are inlined into a <script> tag:

<script>
const age =
const name = ""
if (age > 18 && name.length) {
    document.write(`Welcome to my adult website ${name} 8=D`)
} else {
    document.write(`Go away`)
}
</script>

Constraints

  • age — maximum 2 characters, no blacklist.
  • name — filtered through the regex [^a-z$`{}/].

Goal

Trigger alert(window.name).

Exploitation

  1. Put a double quote and a backslash into age: "\. The backslash escapes the newline so the next line continues the previous statement.
  2. Start name with two semicolons, drop the payload, then close with //: ;;alert(window.name)//.
  3. The injected text becomes a fresh executable statement and the alert runs.

Proof of Concept

  • age: "\
  • name: ;;alert(window.name)//

Why It Works

The backslash on age escapes the literal newline in the generated source, gluing the name line onto the previous statement. A leading ; opens a new statement and // comments out the trailing characters.

The regex is the weak link — it scans for blacklisted characters once. Feed it two of the same forbidden character and the check passes both through, because nothing tracks that a violation already occurred.
